Create the first working triage rubric for this repository cluster.

Define how the company will identify:

- `BACKLOG` items that are waiting for human review versus `TODO` items ready for QA work
- actionable issues that should receive exactly one GitHub `type:` label
- needs-clarification issues
- duplicates
- stale or superseded items
- out-of-scope requests
- unreproducible bugs that require an internal closure proposal
- questions that require a board-approved answer proposal
- PRs that are ready for maintainer merge versus PRs that require engineering, QA, architect, or maintainer action

Keep the rubric simple enough to run every sweep without debate.
